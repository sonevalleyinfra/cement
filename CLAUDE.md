# Rules for AI assistants working on this project

The owner is a beginner. Explain what you change in plain language and keep solutions simple.
Read the official docs for the installed version before using an API. Never guess.
Next.js docs are bundled in `node_modules/next/dist/docs/`.

## Workflow

- **Never commit to `main`.** Make every change on a new branch and open a pull request.
  `pnpm ship "<description>"` does all of it (checks, branch, commit, push, PR); prefer it.
- Before opening the PR, all of these must pass: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`.
- Merge only when the owner asks, and only with `pnpm release` (it refuses red or conflicting PRs).
- **Add a test for every business rule** you add or change: money maths, permissions, validation,
  status changes, limits, dates and so on. Tests live next to the code as `*.test.ts` and run with Vitest.
  Put rules in plain functions (no database, no request) so they are easy to test.

## Database (Drizzle)

- Schema lives in `src/db/schema/` and is exported from `src/db/schema/index.ts`.
- **Change the database only through migrations:** edit the schema, run `pnpm db:generate --name <change>`,
  commit the generated files in `/drizzle`. Migrations run automatically when the container starts.
- **Never run `drizzle-kit push`** (or `db push`) against any real database (staging, preview, production).
  Never edit or delete a migration that may already have run anywhere; add a new one instead.
- Use `timestamp(..., { withTimezone: true })` for all timestamps.
- `src/db/schema/auth.ts` is generated by `pnpm auth:generate` (Better Auth CLI). If you regenerate it, keep
  `withTimezone: true` on every timestamp and then create a migration.
- Use the shared `db` from `@/db`. Do not create new connection pools (the pool is capped at 5).

## Environment variables

- **All env vars go through `src/env.ts`.** Never read `process.env` anywhere else.
- To add a variable: add it to the schema in `src/lib/env-schema.ts`, add a test in `env-schema.test.ts`,
  document it in `.env.example` and the README table.
- Integration keys (Razorpay, LiveKit, Google, Firebase...) come from the owner's key safe `~/.config/app-factory/`.
  List them in `.env.example` with an **empty** value if production requires them (see `/integrate`).
  Never read the key safe or ask for key values; the owner adds them with `pnpm keys set`.
- Never put secrets in `NEXT_PUBLIC_*` variables. Those are visible in the browser.
- Never import `@/env`, `@/db`, `@/lib/auth` or `@/lib/email` from a `"use client"` file.

## Auth (Better Auth)

- **Every protected page** starts with `await requireUser()` or `await requireAdmin()` from `@/lib/session`.
- **Every server action** (`"use server"`) starts with `await requireUser()` or `await requireAdmin()`,
  even if the button is only shown to signed-in users. Server actions are public HTTP endpoints.
- Check ownership too: a user may only read or change their own records unless they are admin.
- Check roles with `isAdmin()` from `@/lib/roles`, not by comparing strings.
- Do not add `proxy.ts` (middleware) as the only protection. It may do optimistic redirects at most.

## Email

- **All email goes through `sendEmail()` / `sendEmailInBackground()` in `src/lib/email`.**
  Never import `resend` anywhere else. This keeps `EMAIL_MODE` (log / allowlist / live) working.
- Put new email content in `src/lib/email/templates.ts`, with a plain-text version.

## Money, dates, locale (India)

- **Money is always an integer number of paise** (₹1 = 100 paise). Store it in `integer` or `bigint`
  columns, never `real`, `double` or `numeric`-as-float. Never use floating-point rupees in calculations.
- Use helpers in `src/lib/money.ts`: `formatINR`, `formatINRCompact`, `parseRupeesToPaise`, `splitPaise`, `percentOf`.
  Add new money rules there, with tests.
- Show dates with `formatDate` / `formatDateTime` / `toISTDateKey` from `src/lib/datetime.ts`
  (Asia/Kolkata). The server runs in UTC, so never call `toLocaleString()` without a time zone.
- Locale is `en-IN`, see `src/lib/locale.ts`.

## UI

- Use shadcn/ui components from `src/components/ui` (add more with `pnpm dlx shadcn@latest add <name>`).
  Style with Tailwind classes.

## Deployment

- Coolify builds the `Dockerfile`. On start, `docker-entrypoint.sh` runs migrate, then seed admin, then the server.
- `pnpm build` must work with **no** environment variables (Coolify does not pass runtime secrets to the build).
- Keep `/api/health` returning 200 only when the database answers.
